      How to read the replays

      What you are watching

      Mapping one session (T1)

      Each system maps the session on its own. The replay draws its final trajectory, after all loop closures, along the session's timeline, aligned to the ground truth (dashed) as the benchmark scores it: rigidly (SE(3)), or with scale (Sim(3)) for the monocular baselines, which get no metric input. CROSS's monocular runs estimate metric scale and are aligned rigidly, which is stricter. ATE is the root-mean-square position error of that trajectory.

      • A run that tracked only part of the session shows only that part and stops where its estimate ends (×). Below 80% of the session it counts as failed.
      • The published paths carry no timestamps, so the replay times each estimate by matching it, in order, to the ground truth.

      Localization in a stored map (T2)

      Each system that can save a map builds one from the map session and saves it. The query session, another recording of the same place, then runs once from its first frame with no initial pose. The route is coloured by one system's state: localized within the radius, wrong (beyond it), or no pose in the map yet.

      • As in the benchmark, only frames the map covers and where the robot moves are scored. Final recall is the share of them localized within the radius.
      • Systems that cannot save a map run the map session and the query session as one stream. MASt3R-SLAM, VGGT-SLAM 2.0 and AMB3R-SLAM log their poses after their final optimization, which favours them. LingBot-Map has no relocalization step, so every query pose counts: its numbers are upper bounds.

      Data: the published benchmark results of 2026-10-23 (commit b2507d0), 9,198 runs in all. Every run replayed here is in the full results (select a table cell to see its runs), and the benchmark summary ranks the systems; the rules are in the protocol.
