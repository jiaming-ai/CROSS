What it does

One system for the whole multi-session loop

Build a map, save it, come back days or seasons later, find where you are, keep tracking and extend the map. Every clip below is a real run.

Multi-session localization

Relocalize in a map from another session

Start anywhere in a stored map, at night, in snow, in a crowd or with the lights off, and CROSS finds where it is. Each visual match becomes a pose hypothesis that odometry must confirm before it touches the map, so look-alike places cannot corrupt it.

Any sensor setup

RGB-D, stereo or one camera; wheel odometry, a VIO, an IMU or nothing at all. Fourteen ready-made modes, picked with one flag.

Accurate when others drift

Loop closures pass consistency tests before they bend the map, so trajectories hold in the dark, in glare and through sharp turns.

Kilometre-scale maps

Sessions of several kilometres, indoors and out. Compact maps on disk, pose-graph optimization in the background, optional GNSS anchoring.

One map, another camera

Build the map with one camera and relocalize with another, such as a colour camera in a stereo camera's map.

Light robot, GPU server

The robot runs its odometry and sends a few images; a GPU server runs the model and the map. No PyTorch on the robot.

The map becomes a 3D world

Turn a saved map into a 3D Gaussian-splatting world you can fly through, built from the map's own keyframes.

Many robots, one map In development

Several robots map at the same time and join one shared map. Recorded sessions replayed together; not in the released code yet.

Benchmark

Ahead on every task of the benchmark

CROSS and 6 open-source SLAM systems ran through one protocol on the same sessions: map a session, localize another session in that stored map, and relocalize from cold starts.

  • 9,198 runs on four datasets: indoor robots, a campus over 14 months, driving, and simulated change.
  • Same inputs: every system gets the same images, and the same odometry when it takes odometry.
  • Open: the protocol, the runners for every system and all per-run results are public.

How it works

A match is only a hypothesis until odometry agrees

Place recognition alone confuses look-alike places, and one false loop closure can ruin a map. CROSS keeps competing answers alive and lets the robot's own motion decide between them.

  1. 1Remember places

    The map is a graph of keyframes (images and their poses) linked by odometry and by verified loop closures. It is saved to disk and loaded in every later session.

  2. 2Hypothesize poses

    Place recognition retrieves keyframes that look alike. One pass of a multi-view model, or PnP on depth, turns each into a metric pose. Competing poses live side by side in a Gaussian mixture on SE(3).

  3. 3Let odometry decide

    As the robot moves, hypotheses that disagree with its odometry lose weight and die out. A new session joins the map only when its placement holds over several steps and places.

  4. 4Commit what holds

    A loop closure enters the map only after statistical consistency tests, then pose-graph optimization removes the drift. Look-alike places never reach the map.

Get started

Up and running in minutes

One script installs everything into a local environment and downloads the models. Then map a session, save it, and relocalize the next session in it.

  • Linux and an NVIDIA GPU with CUDA, about 10 GB of disk
  • Reads RGB-D and stereo folders, KITTI, TUM RGB-D, OpenLORIS, TartanAir and iPhone (Record3D) recordings
  • Python API: feed frames, read poses in the map's coordinates
  • MIT-licensed code; the RGB-D modes with PnP use no non-commercial model
Read the docs View on GitHub
Terminal
# install: a local .venv with PyTorch, CROSS and the models
$ git clone https://github.com/jiaming-ai/CROSS.git && cd CROSS
$ bash install.sh --stereo
$ source .venv/bin/activate

# session 1: build a map and save it
$ python run.py data/posed/office1-1 --mode rgbd_wheel \
    --save-map maps/office/map.pkl

# session 2: relocalize in it, write poses in the map frame
$ python run.py data/posed/office1-2 --mode rgbd_wheel \
    --load-map maps/office/map.pkl --save-poses office1-2.txt
