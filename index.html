Summary

CROSS maps a place once and finds its way back into that map in every later session: at night, across seasons, after the furniture moved, or with another camera. It treats every visual match as a pose hypothesis and commits only what the robot's own motion confirms, so a single look-alike view cannot corrupt the map. RGB-D, stereo or monocular; with wheel odometry, a VIO, an IMU or none.

How it was measured

Overview

Relocalization

Start anywhere in a map from another session, at night, in snow, in a crowd or with the lights off, and CROSS finds where it is: 88% of cold starts outdoors with cameras only, where the best other system manages 39%.

Any sensor setup

RGB-D, stereo or one camera, with wheel odometry, a VIO, an IMU or nothing at all: fourteen ready-made modes, picked with one flag.

Large scale

Sessions of kilometres, indoors and out, kept accurate by verified loop closures, stored compactly on disk and, with GNSS, placed on the Earth.

Deployment

One map, used the way your robot needs it: with another camera, with the heavy work on a GPU server, and soon shared by several robots.

Method

Place recognition alone confuses look-alike places, and one false loop closure can ruin a map. CROSS keeps competing answers alive and lets the robot's own motion decide between them.

  1. 01

    Remember places

    The map is a graph of keyframes, images with their poses, linked by odometry and by verified loop closures. It is saved to disk and loaded in every later session.

  2. 02

    Hypothesize poses

    Place recognition retrieves keyframes that look alike. One pass of a multi-view model, or PnP on depth, turns each into a metric pose. Competing poses live side by side in a Gaussian mixture on SE(3).

  3. 03

    Let odometry decide

    As the robot moves, hypotheses that disagree with its odometry lose weight and die out. A new session joins the map only when its placement holds over several steps and places.

  4. 04

    Commit what holds

    A loop closure enters the map only after statistical consistency tests; pose-graph optimization then removes the drift that built up in between.

Get started

Linux, NVIDIA GPU, about 10 GB

One script installs everything into a local environment and downloads the models. Then map a session, save it, and relocalize the next session in it.

  • ReadsRGB-D and stereo folders, KITTI, TUM RGB-D, OpenLORIS, TartanAir, iPhone recordings (Record3D)
  • Install--stereo covers the RGB-D and VGGT-Omega modes; --mono adds DPVO and the monocular IMU modes
  • Pythonfeed frames, read poses in the map's coordinates
  • LicenceMIT-licensed code. The learned models (VGGT-Omega, Depth Anything 3) are for non-commercial research; the RGB-D modes with PnP use neither

Terminal

  1. # install: a local .venv with PyTorch, CROSS and the models
  2. $ git clone https://github.com/jiaming-ai/CROSS.git && cd CROSS
  3. $ bash install.sh --stereo
  4. $ source .venv/bin/activate
  6. # two recordings of one office (OpenLORIS-Scene; download: see the docs)
  7. $ python scripts/datasets/convert_openloris.py data/openloris/office1-1 data/posed/office1-1
  8. $ python scripts/datasets/convert_openloris.py data/openloris/office1-2 data/posed/office1-2
  10. # session 1: build a map and save it
  11. $ python run.py data/posed/office1-1 --mode rgbd_wheel \
  12. --save-map maps/office/map.pkl
  14. # session 2: relocalize in it, write poses in the map frame
  15. $ python run.py data/posed/office1-2 --mode rgbd_wheel \
  16. --load-map maps/office/map.pkl --save-poses office1-2.txt
